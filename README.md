> **把客户的复习资料，变成一套"敢交付"的题库。**
> AI 出题 → 多模型交叉质检 → 人工裁决 → 立刻可刷；成本可控、过程可审计、操作可撤回。

这不是一个"调一次大模型 API"的脚本，而是一个能跑起来的**多用户平台**：账号体系、余额计费、
操作审计与撤回、任务持久化、知识点驱动的自然语言制题，全部落在 MySQL 里 —— 而后端
**只用了 1 个第三方依赖**（MySQL 驱动），无框架、无构建链。

## 核心亮点

| 亮点 | 做了什么 |
|---|---|
| **多模型交叉质检** | 每道题由 2 家**异构模型**独立重解，且不把已有答案给它们（避免模型附和）；全员答案一致才自动入库，任何分歧转人工队列——刻意不做多数表决，避免"两票对一错"掩盖真实问题 |
| **质量可量化** | 金标集评估：用已人工验算的真题当考卷测质检准确率，**严格区分"答对 / 答错 / 未答"**并设 20% 未答率守门（防止"调用全失败却判 100% 通过"） |
| **成本可控** | 事前按资料规模 × 题量 × 质检家数生成报价单；任务级预算硬闸，超支自动暂停；扣费走事务 + 行锁 + 幂等键，**既不重复扣也不漏扣** |
| **敢管责任** | 操作记录按「用户 / 管理员」分离，每个账号有唯一用户号可按号直查；误删资料、误充值、审错的题都能**一键撤回**（写补偿操作，而不是删日志） |
| **长资料真能覆盖** | 按章节/考点**分块检索取材**（取代旧的"只喂前 12000 字"），跑完输出知识点覆盖率并自动补齐未覆盖考点 |
| **性能有实测** | 5 万题、并发 30 实测：**写 QPS 25 → 528、读 10.7 → 52**（两轮优化：物化排序优先级消除全量 filesort、单行状态查询取代全量加载）——过程与卡点见 [docs/PERF.md](docs/PERF.md) |

## 它解决什么问题

接考研专业课资料制单时，真实痛点有四个：

1. **单题成本不透明**——一份 200 页的资料能出多少题、要烧多少 token、该报价多少？凭感觉定价，要么亏要么吓跑客户。
2. **AI 出的题不敢直接用**——大模型会一本正经地给出错误答案，错题到客户手里就是口碑事故。
3. **做完就丢**——上传的资料、跑完的任务、生成好的题目，关掉浏览器就没了。
4. **成本无法控制**——学生用户反复看同样的题、重复制题，钱白花。

QuestionForge 的答案是：**接单前先算钱（报价单），出题后强制互检（多模型交叉验证），一切落库（随时可回），按进度推送（省钱）**。

## 用户旅程

```
注册/登录（scrypt 加盐，HttpOnly Cookie 会话；第一个注册的账号自动是管理员 admin1）
   │
   ├─ 💬 对话制题 ── 资料三种来源（资料库选用 / **页内上传 PDF·Word** / 粘贴文本）任选其一
   │                 → 🤖 AI 先通读资料梳理知识点 → 一句话说需求（含"每个知识点各出 2 道""所有题型各一道"）
   │                 → 解析成制题命令 + 报价 → 确认后自动制题（也可「先存为待批准任务」稍后手动启动）
   │
   ├─ 📂 我的资料库 ── 上传的资料、抽取的图片、识图结果持久保存，随时复用；可预览、可删除（软删除，可撤回恢复）
   │
   ├─ 📋 制题任务 ── 实时进度、待批准报价可直接续跑、人工审核分歧题、知识点覆盖率、导出科目包
   │
   ├─ 📝 我的题库 ── 制完题即可开刷：按制题批次分组 · 练习（章节/题型/难度/批次筛选）· 错题本 · 收藏 · 统计
   │                  选择题即时判分（支持键盘 1-4 / A-D）、主观题自评；错题自动进错题本并优先推送
   │                  AI 讲解 + 连续追问（按实际用量计费，对话上下文存数据库）
   │
   ├─ 👤 个人中心 ── 用户号、余额、每日签到、累计在线时长、账务流水、登录设备（可踢下线）、
   │                  改密码、操作记录（只含本人操作，可一键「申请撤回」）
   │
   └─ 🛡 审计与撤回 ──（管理员）待处理撤回申请一键批准 · 审计日志按用户号查询/导出 CSV · 签到看板
```

**用户与管理员的记录彻底分开**：`oplogs.scope` 区分 `user` / `admin`，普通用户在个人中心只看得到自己的操作；配置、供应商、授权、评估这类管理动作只出现在「审计与撤回」页。每个账号有唯一**用户号**（管理员 `admin1` 起、普通用户 `u1` 起，升降级不改号），审计查询就是一条 SQL：

```sql
SELECT * FROM oplogs WHERE user_no = 'u1' ORDER BY id DESC;
```

**后台任务**（右下角面板）：上传资料、解析 PDF、识图这类耗时操作做成后台任务——**随时切页面、去看别的，任务照常进行**，进度显示在右下角面板（可收起）。原理是识别任务在服务端独立执行，客户端只是查进度，因此关掉页面也不影响。制题任务同理：流水线在服务端跑，任务页只是看板。

**账号菜单**（右上角头像）：个人中心 / **切换账号** / **退出登录**。退出时服务端销毁会话、客户端清空全部缓存（任务、题库、资料列表、草稿），换账号后看不到上一个账号的任何残留；服务器上的数据（余额/资料/题库）全部保留，下次登录继续用。


**资料的三条入口**（都在「对话制题」页里）：

| 入口 | 适合场景 | 图片处理 |
|---|---|---|
| **资料库选用** | 已有资料复用（推荐） | 库里已归档的图直接关联，题目可引用、导出内嵌 |
| **页内上传 PDF/Word** | 新客户、新资料 | 当场抽图 → 可选交视觉模型识图 → 结果一键存进资料库 |
| 粘贴文本 | 临时小段内容 | 无图 |

在「对话制题」页顶部有**资料选择器**：选资料库里的资料会自动隐藏粘贴框，只需写需求即可。

**制题流水线**（每一步都计量成本）：

```
资料摄取（页面分类：原生文字 / 扫描OCR / 图形抽取 + 注入清洗）
   → 知识点梳理（AI 通读资料列出考点清单，规则兜底；结果入库复用）
   → 识图（视觉模型把图读懂成可解题文字）
   → 成本预估 → ★人工闸门：批准报价与预算
   → 出题（按考点分块检索取材 + 注入经验库 + 薄弱考点倾斜）
   → 难度标注
   → 近似重复检测（命中打标，不自动入库）
   → 交叉质检（≥2 家不同厂商模型独立重解，禁止参考已有答案）
   → 裁决（全员一致→自动入库；任何分歧→人工队列）
   → 人工审核（采纳/修改采纳/打回/毙掉）→ 修改口径沉淀进经验库
   → 知识点覆盖率检查（哪些考点还没出到题）→ 导出科目包
   → 结算（流水线每次停下都按实际用量入账，幂等不重复扣）
```

**资料不再被截断**：旧实现把整份资料截成前 12000 字塞进提示词，200 页资料后半本永远出不到题。
现在按"标题/空行/长度"切成语义块（`lib/text.js`），出题时按**考点 + 章节**检索最相关的块注入，
并记录哪些块已经用过 —— 多批次跑完自然覆盖全篇。报价按真实注入量估算，不再虚报。

## 数据流程（为什么刷新后数据还在）

**唯一的真实数据源是 MySQL。** 页面不缓存业务数据，每次进入都是从数据库现取：

```
你的操作（注册/充值/上传/制题/审核/隐藏题目…）
   → 前端调用后端接口
   → 后端写入 MySQL（users / materials / tasks / questions / oplogs …）
   → 页面重新从数据库读取并渲染
```

具体到每一处：

| 页面 | 数据来自 | 何时刷新 |
|---|---|---|
| 侧边栏余额 | `users.balance` | 每次操作后 + 每 8 秒 |
| 个人中心余额/操作记录 | `users.balance` + `oplogs` | 进入页面时 |
| 我的资料库 | `materials` / `figures` | 进入页面时 |
| 制题任务列表 | `tasks`（按 user_id） | 进入页面时 |
| 任务详情/进度/日志 | `tasks` / `questions` / `events` | 进入页面时 + 运行中每 2 秒 |
| 我的题库 | `questions` + `qstate`（学习进度） | 进入页面时 |
| 模型配置 | `data/config.json`（管理员） | 进入页面时 |

> 说明：API Key 与模型配置存在服务器本机文件（不进数据库、不下发普通用户），其余业务数据全部入库。

## 数据设计（MySQL）

| 表 | 存什么 | 敏感数据保护 |
|---|---|---|
| `users` | 账号、**用户号**、余额、角色 | **密码 scrypt 加盐散列，不可逆**；余额只本人可见 |
| `sessions` | 会话 token、过期时间、**在线时长累计** | token 随机 256 位，HttpOnly Cookie 下发，7 天过期；登出只标记结束（保住已累计时长），90 天后清理 |
| `materials` / `figures` | 客户资料全文、图片路径、识图结果 | 按 user_id 隔离；**删除为软删除**（可撤回恢复） |
| `tasks` / `questions` | 任务、题目、质检裁决、人工结论、知识点、取材覆盖 | 全部持久化，断点可续，按 user_id 隔离；人工结论**不会被流水线回写覆盖** |
| `events` | 每次 LLM 调用、token、费用、裁决 | 全程留痕可回放 |
| `oplogs` | 操作记录（含 `scope` 用户/管理员、`user_no`、结构化参数） | 仅本人可读自己的操作；管理操作只在管理端审计可见；按用户号一条 SQL 直查 |
| `bills` | 账务流水（扣费/充值/退回，只增不改） | `idem_key` 唯一键保证"同一件事只扣一次"；记欠费与扣后余额 |
| `qstate` | 学习进度（做过几次、错几次、是否隐藏/收藏、上次对错） | 驱动"按进度推送" |
| `attempts` | 每次答题流水（时间/对错/作答内容/自评分） | 统计与错题本的依据 |
| `qchats` | 逐题 AI 讲解对话（含追问上下文） | 换设备后仍可接着追问 |
| `checkins` | 每日签到（连续天数、历史最长） | `(user_id, day)` 主键天然幂等 |
| `kps` | 从资料抽出的知识点清单 | 出题取材与覆盖率检查的依据 |
| `revert_requests` | 撤回申请与审批结论 | 用户申请、管理员审批，撤销动作写补偿记录而非删日志 |
| `schema_migrations` | 迁移版本记录 | 建表/改表全部走版本化增量迁移，启动自动执行 |

**权限模型**：首个注册用户自动成为管理员（用户号 `admin1`）。普通用户只能看到自己的资料、任务、题库和余额。API Key 只存服务器本机 `data/config.json`，接口回显一律打码，普通用户请求直接 403。写操作另有 Origin 校验（防 CSRF）与接口限流。

## 省钱设计：按进度推送

学生反复看已经会的题是纯粹的浪费。题库推送排序（`/api/my/questions`）：

1. **错题优先**（答错次数越多越靠前）——最该复习的先来
2. **没做过的新题**次之
3. **已会的题**最后，只做巩固

配合两个动作：
- **隐藏**：不需要的题一键隐藏（`POST /api/my/hide`），不再推送，但题目仍在数据库里可恢复
- **复制/微调**：同一批题目按用户需求调整时，保留不需要的、只重做要改的（人工审核里的「打回重新生成」只重生成单题，不整批重跑）

## 企业级设计要点

| 能力 | 实现 | 为什么重要 |
|---|---|---|
| **多模型交叉质检** | 每道题由 2+ 家不同厂商模型独立重解，只有全员一致才自动入库 | 单一模型的系统性错误无法被自己发现；异构模型的分歧是高质量的错误探测器 |
| **密钥池与故障切换** | 岗位可绑多个供应商：并发时按负载轮换；Key 失败自动冷却并切换；全挂才报错 | 单 Key 被限流是全平台停摆的常见原因，轮换 + 冷却让服务不中断 |
| **并发闸** | 全局 + 单供应商双层信号量，超出排队而非打爆上游 | 多用户同时制题时既保住吞吐，又不触发限流 |
| **配置兜底** | 岗位未配 Key 自动回退主供应商；完全无 Key 时降级为本地规则解析 | 避免"点一下就 401"这类低级故障 |
| **自然语言制题** | NLU 把"出 10 道选择题，重点考时间复杂度，中等难度"解析成结构化命令 | 用户不必理解表单字段，直接说人话 |
| **双通道资料摄取** | 页面分类：原生文字直取 / 扫描页本地 OCR / 图形页交视觉模型 | 一份真题 PDF 实测 47 张图、12 页纯图，纯文字提取会丢掉 1/3 内容 |
| **成本可预测 + 余额硬闸** | 报价单按资料规模×题量×质检家数×识图张数估算；余额不足直接拒绝建任务 | 把"凭感觉报价"变成成本加成，防止超支 |
| **幂等与断点续跑** | 沿"需求/题目/质检员"三维记进度，重复调用只补缺失 | 关电脑、崩了都能续，不产生重复题 |
| **提示注入防护** | 客户资料视为不可信输入：模式匹配 + 隔离标记 + 明确"这是数据不是指令" | 资料里藏指令不能把 agent 带偏 |
| **人工审核闭环** | 分歧题人工裁决；修改后采纳写入经验库，后续出题自动注入 | 人负责最后 10% 的判断，且判断会变成 agent 的记忆 |
| **全程可观测** | 每次调用、token、费用、裁决落 `events` 表，控制台实时看 | 出问题能定位到具体哪一步、哪个模型 |
| **质量可量化** | 金标集评估：用已验算的 853 真题当考卷测质检准确率，85% 为自动入库阈值 | 让"能不能自动入库"变成数据决策 |
| **零第三方框架** | 后端只用 Node 内置模块 + mysql2 驱动 | 无 Express、无 ORM，代码即文档，易审计 |

## 账号与管理员

登录页可直接注册（自助使用）。**平台第一个注册的账号自动成为管理员**，之后注册的都是普通用户。

需要更多管理员时，管理员可在「👥 用户管理」页：

| 操作 | 说明 |
|---|---|
| 创建管理员账号 | 直接填用户名密码创建，无需再抢"第一个注册" |
| 设为管理员 / 取消管理员 | 把已有账号提升或降级；**不能取消最后一个管理员**（防止平台无人可管） |
| 查看全部账号 | 每个账号的余额、任务数、资料数、题目数、答题数，一眼看出谁是空号/测试号 |

普通用户看不到管理页，接口层也会返回 403（前端隐藏 + 后端强制校验，两层都在）。

> 忘记管理员密码时：用 `node -e` 直接改库里的 `users.role`，或注册一个新账号后手工把它的 role 改成 admin。测试脚本产生的账号可用 `node cleandata.js --yes` 清理。

## API 池与高并发（管理员）

「🔑 API 池」页集中管理所有模型凭据，解决三件事：**多个 Key 的批量配置、一个岗位用多个 Key、并发与故障容错**。

### 供应商密钥池

凭据统一存在「供应商」里（名称 / Base URL / API Key / 单价），岗位只声明"用哪些供应商"：

| 岗位 | 说明 | 建议 |
|---|---|---|
| `generator` 出题员 | 生成题目 | 能力最强的模型 |
| `classifier` 难度标注员 | 分析难度 | 便宜模型 |
| `verifier1/2…` 质检员 | 独立重解每题 | **至少 2 家不同厂商**（异构分歧才有信息量） |
| `vision` 识图员 | 图形→文字 | **必须支持视觉**（GLM-4V / Qwen-VL） |
| `nlu` 需求解析员 | 自然语言→制题命令 | 便宜模型 |

**一个岗位可以绑定多个供应商**，这时：
- 并发请求自动**轮换分散**（按当前负载挑最空闲的 Key）
- 某个 Key 报 401/403/429/5xx 或超时 → **自动冷却并切换到同岗位的其它 Key**，用户无感
- 全部不可用才报错，并给出明确原因

### 模型跟供应商走（模块化的关键）

**模型名存在供应商上，不绑在岗位上**：

| 位置 | 含义 |
|---|---|
| 供应商的「模型」列 | 该供应商的**默认模型**（如 DeepSeek → `deepseek-chat`） |
| 岗位的「模型覆盖」列 | **可选**，留空就用供应商默认（同供应商要跑不同模型时才填，如识图用 `glm-4v-flash`） |

解析优先级：**岗位覆盖 → 供应商默认**。所以：

- 把某岗位从智谱换成 DeepSeek，模型自动变成 `deepseek-chat`，不会残留 `glm-4-flash` 去打错接口
- 同一个智谱 Key 可以既供文本质检（`glm-4-flash`）又供视觉识图（`glm-4v-flash`），靠岗位覆盖区分
- **想用两个 DeepSeek Key 互检**？批量导入两条 DeepSeek（不同 Key、同一模型名），分别绑给质检员A/B 即可

「金标集评估」页顶部会明确列出**本次实际会调用哪个供应商、哪个模型**（含来源标注），改完 API 池即时生效；历史报告里也记下了当时用的模型，两者不会混淆。

### 批量配置

「批量导入」支持一次粘贴多行（逗号/制表符/竖线分隔均可，`#` 开头为注释）：

```
DeepSeek-主,https://api.deepseek.com,sk-xxxxxxxx,2,8
DeepSeek-备,https://api.deepseek.com,sk-yyyyyyyy,2,8
智谱GLM,https://open.bigmodel.cn/api/paas/v4,xxxxxxxx,1,1
```

导入时可选择直接绑定到某个岗位。配好后点「测试全部」逐个真实调用一次，确认哪些可用。

### 并发控制

| 参数 | 默认 | 作用 |
|---|---|---|
| 全局并发上限 | 8 | 全平台同时进行的模型调用数（超出排队，不丢请求） |
| 单供应商并发上限 | 4 | 防止把某个 Key 打爆被限流 |
| 失败冷却 | 30 秒 | Key 失败后的冻结时长（429 限流自动加倍） |

页面顶部实时显示「运行中 / 排队」与每个供应商的成功/失败计数、冷却剩余时间，可手动「清除所有冷却」。

### 兜底：岗位没配 Key 也不会 401

若某岗位绑定的供应商都没有 Key，会自动**回退到主供应商**（第一个配了 Key 的）。所以不会出现"多点了一个按钮就 401"——最多是用错模型。同时 `/api/chat/parse` 在完全没有可用 Key 时降级为本地规则解析，保证基本可用。

> 配置里不存在的岗位不会被"回退"凭空创造出来（例如只配了 `verifier1/2` 就不会莫名多出 `verifier3/4` 参与质检）。

## 刷题功能已内置

平台自带完整刷题系统（就是原来独立刷题系统的能力搬进来了），**制完题立即可刷**：

| 能力 | 说明 |
|---|---|
| 练习 | 按章节/题型/难度/批次筛选；题目按"错题 → 未做 → 已会"智能排序 |
| 判分 | 选择题点选即时判分并给解析；主观题对照参考答案后自评（掌握/半对/未掌握） |
| 错题本 | 答错自动收录，答对后自动移出；支持"重做"从统计页跳回该题 |
| 收藏 | 任意题目可收藏，形成个人重点题集 |
| 统计 | 总正确率、按章节/题型正确率、最近 60 条答题流水 |
| AI 讲解 | 单题逐步讲解 + **连续追问**（上下文存库，换设备接着问） |
| 原图 | 含图题目直接渲染原图（服务端鉴权后输出，不暴露文件路径） |
| 隐藏 | 不需要的题可隐藏（不再推送，但仍在数据库可恢复） |

导出的科目包（`.js`）仍可用于交付给**外部**刷题客户端（[853刷题系统](../853刷题系统)），但平台内部使用已经不需要这一步。

## 部署

**方式一：本机直接跑**（依赖 Node 20+、MySQL 8、Python 3 + pymupdf/pillow/pytesseract）

```bash
npm install
node server.js          # 首次启动自动建库建表并执行迁移
```

配置一律可用环境变量覆盖（见 `.env.example`），不改代码：`QF_DB_*`、`QF_PORT`、`QF_LOG_LEVEL`、`QF_SECURE_COOKIE` 等。

**方式二：Docker**

```bash
docker compose up -d --build     # → http://localhost:8540
```

**生产部署务必注意**：
- 前面加一层 HTTPS 反向代理（Nginx/Caddy），并设置 `QF_SECURE_COOKIE=1`（Cookie 才会带 `Secure`）；
- 改掉默认数据库口令，数据库不要暴露到公网（compose 里已限制为只监听 127.0.0.1）；
- 探针用 `GET /api/health`（含数据库连通性与 schema 版本）；
- 日志默认 JSON 行输出到 stdout 并落盘 `data/logs/app-YYYY-MM-DD.log`，可直接接 filebeat/loki；
- 停机请用 `SIGTERM`（容器 stop 即是），服务会等正在跑的流水线收尾并结算费用后再退出；
- API Key 明文存在 `data/config.json`，迁移/备份时按密钥对待。

## 已知边界

- **人工审核不可省**：分歧题必须人裁决。AI 做完确定的 90%，人负责最后 10%。
- **充值未接支付网关**：`/api/user/recharge` 为模拟充值（直接加余额），正式商用需接入真实支付并做对账（账单表已为对账打好基础：只增不改 + 幂等键）。
- **计费时点**：v3 起"流水线每次停下就结算已花部分"（旧版只在完全跑完时扣一次，只要有分歧题就永远不扣费）。对用户总账一致且幂等，但余额会在任务进行中就开始减少。
- **复习侧还没做间隔重复**：本次做到"批次分组 + 错题优先 + 按知识点正确率 + 薄弱考点倾斜出题"，真正的记忆调度（FSRS/SM-2、到期时间、每日计划、掌握度模型）与组卷/模拟考/打印导出是下一版的事。
- **在线时长从 v3 开始统计**：历史会话没有时长数据（显示 0 属正常）。
- **资料删除是软删除**：列表与取材都看不到，但正文与图片仍在库里，可从操作记录撤回恢复；物理清理需自行执行 SQL。
- **图片存磁盘不入库**：MySQL 只存路径，二进制在 `data/uploads/`。数据迁移需一并搬运（未上对象存储）。
- **视觉模型需另配 Key**：DeepSeek 主接口看图不支持；按张计费，图形密集资料成本会上升（报价单已单列）。
- **OCR 公式会失真**：`O(log₃n)` 可能被认成 `O(log,n)`，含公式的扫描件建议走视觉通道。
- **各厂商 max_tokens 上限不同**：实测智谱 GLM-4V 限制 `max_tokens ≤ 1024`，传大会直接 400 报错。识图默认按 1000 调用（可在岗位配置里加 `maxTokens` 覆盖）；换视觉模型时建议先用 2 张图试跑。
- **CSRF 用的是 Origin 校验**：对浏览器跨站写请求有效（curl/脚本不带 Origin 故放行）。若要令牌式防护，需前端配合改造。
- **交付防拷贝**：静态科目包无法技术性防转卖，靠包名嵌客户代号溯源。
- **清理数据务必用 `cleandata.js`**：开发期不要用 `DELETE FROM users` 这类全表删除——本项目开发中真实发生过一次，把使用者的账号与余额一起删了。`cleandata.js` 只删测试前缀账号，默认预演，且会先列出将被删除的内容。
